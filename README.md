# 娱乐法合同审查｜MCN · 直播电商 · 达人经纪

一个给律师和 MCN 法务用的 AI 技能：把经纪合约、直播带货协议、账号权属、竞业限制这类行业合同丢进来，按 **62 个行业判断点**逐条过一遍，直接给出「红线在哪、该改成什么、依据是哪一条」。

---

## 认知基线（先看这个）

娱乐法合同的风险，八成不在"条款写得难看"，而在**行业惯例与法律定性错位**——条款按行业习惯写得很顺，但放到法庭上定性就变了。下面三条是这套技能反复强调、也是最容易被通用合同审查漏掉的：

**① 情势变更 ≠ 不可抗力。** 合同里写"政策变化按不可抗力处理"看起来很周全，但遇到平台改规则、品类被下架这类情形根本用不上。《民法典》第 533 条（情势变更：基础条件重大变化 → 重新协商 → 请求变更或解除）和第 590 条（不可抗力：免责 + 及时通知 + 合理期限内举证）是两条不同的路，构成要件、举证责任、法律后果都不同。只写不可抗力的，等于把情势变更这条路自己堵死。

**② 竞业限制写进合作合同，本身就是认定劳动关系的证据。** 竞业限制是劳动法概念，主播要受它约束，得符合《劳动合同法》第 24 条"其他负有保密义务的人员"——判准是**实际接触商业秘密 + 有保密措施**，不看职级高低。更要命的是反噬：一边在合作合同里写竞业限制，一边不缴社保、发保底工资、搞迟到罚款和休假审批，就是两头输。要么认劳动关系把社保和补偿做实，要么干脆别用"竞业限制"这个词，改成"合作期内独家排他 + 终止后冷却期 + 商业对价"。

**③ 用词决定定性。** 「请假审批」「打卡」「考勤」「排班」在劳动争议里是认定管理从属关系的一票否决词。想对抗"我有正当理由停播"的抗辩，正确写法是**报备**而不是审批，是**未按约开播**而不是旷工，是**违约金／收益不予结算**而不是罚款。改的不是态度，是法律关系。

## 它做什么

覆盖六族共 **62 个判断点**，配 **14 条红线**、**9 组 35 个子案例**的裁判要旨、以及一份八节的审查报告骨架。

| 族 | 场景 | 判断点 | 行业范本 |
|---|---|---|---|
| A | 达人签约（独家经纪、全约、孵化、公会挂靠） | 13 | 12 份 |
| B | 商业变现（直播带货 CPS／坑位费、短视频、代言、代运营） | 14 | 15 份 |
| C | 资产权属（账号、粉丝、著作权、肖像、商标、数据） | 10 | 12 份 |
| D | MCN 特有（劳动关系、竞业限制、保密与商业秘密） | 10 | 8 份 |
| E | 争议处置（解约通知、律师函、违约金、证据固定） | 8 | 5 份 |
| F | 平台合规（类目报白、资质、保证金、平台规则） | 7 | 2 份 |

每个判断点都是五段结构：**识别信号 → 风险分级（🔴🟡🟢）→ 甲方立场改法 → 乙方立场改法 → 检查方法**，并挂上对应的红线编号、判例编号与法条。

### 它输出什么

一份八节结构的审查意见，**第一节永远是「文本体检」**——先查金额大小写是否一致、条款编号是否连续、法律援引是否真实存在、当事人称谓是否统一、空白项是否留坑、条款之间是否互相打架。

六项里查出两项以上矛盾的，结论首行直接写**「建议重做后再审」**，不出漂亮的条款改进清单。理由很实际：文本自相矛盾的合同，逐条改条款是白费功夫，先把底盘修好。

## 防编造自检

`scripts/check_coverage.py` 是这个技能的一部分，也是它跟"网上随便找的合同清单"的区别。十项检查全在防同一件事：**模型把数量、编号、法条、案号说错，而人看不出来。**

| 检查项 | 防的是什么 |
|---|---|
| 总数一致 | 声称 62 个判断点，正文就得真有 62 个 |
| schema ↔ 正文双向 | 注册表里的每一条都能在正文找到，反之亦然 |
| 五段结构 | 判断点缺了"检查方法"就查不出怎么用 |
| 编号连续 | 不许有断号、重号 |
| 红线可解析 | 引用的红线编号必须真实存在 |
| 判例可解析 | 引用的判例编号必须真实存在 |
| 法条必标 ✅ 或 ⚠ | 核验过的标 ✅，没核验的必须标 ⚠，不许含糊 |
| 关键词真落在正文 | 检索关键词不能是编的 |
| 判例册体积上限 | 单册超 1.2 万字就该拆 |
| 对外声明数字一致 | SKILL.md 说 62、README 说 61 这种自相矛盾直接报错 |

```bash
python scripts/check_coverage.py           # 常规检查
python scripts/check_coverage.py --strict  # 有警告也失败
```

> 这套自检不是摆设。第一次跑就抓出七个真实问题，其中「F 族 6 条判断点缺检查方法段」和「子案例数 34 实为 35」两项，是手写时反复核对也发现不了的。

## 依赖

**核心流程零依赖。** 纯 Markdown + JSON，任何支持 Skill 的 AI 客户端都能跑。

| 场景 | 需要什么 | 没有会怎样 |
|---|---|---|
| 常规审查、起草、问答 | 无 | 正常使用 |
| 审 docx 格式的合同 | `python-docx`（MIT） | 提示改用 `scripts/extract_docx.py` 或贴文本 |
| 跑自检脚本 | Python 3 | 按 SKILL.md 里的 checklist 人工核对 |
| 核对法条现行有效性与类案 | 自备法律数据库（可选） | 相关引用一律标 ⚠ 待核验，**不编造条文号** |

法条以 **2026-11** 为基准。技能不发起任何网络请求、不上传合同内容——所有处理在使用者本机完成。

> **许可提示**：本技能不打包、不分发任何第三方组件。若使用者自行安装 OCR 工具处理扫描件，常见方案依赖 PyMuPDF（AGPL-3.0）、RapidOCR（Apache-2.0）。仅本机运行、不分发派生作品通常不触发 AGPL 的源码披露义务；商业闭源分发场景请自行评估或向权利方取得商业许可。

## 适用范围与限制

- **适用**：MCN／直播电商／达人经纪类合同，含独家经纪、IP 孵化与公会挂靠、直播带货、短视频带货、广告代言、代运营、账号转让与租赁、肖像与 IP 授权、主播劳动合同与竞业限制、保密与商业秘密、解约通知与律师函
- **不适用**：影视剧制作发行合同、与 MCN／直播／达人经纪无关的一般民商事合同、诉讼文书
- **不替代律师判断**。输出是办案参考，提示词里立场（甲方／乙方）要明确说，不说时按甲方默认但会在报告首行标注
- 所有法条须使用者核验条文号与现行效力；条款改写建议在签署前应经执业律师复核
